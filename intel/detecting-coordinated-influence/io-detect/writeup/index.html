io-detect: writeup

How a coordination-detection pipeline was built, and what it measured against a labeled influence-operation dataset.

The dataset is gated and no-derivatives, so none of it is redistributed. Anyone reproducing this fetches their own copy from Zenodo under the same terms and verifies it against the checksum above.

A second dataset, the FiveThirtyEight release of the Clemson/Linvill-Warren IRA tweets, ingests through the same canonical schema. It is positives-only and carries no control class, so nothing is scored on it.

Method

  1. Normalize the source into one canonical record schema.
  2. Compute behavioral signals per account and per account pair: co-repost timing, duplicate text, hashtag flooding, mention and reply swarming, automation.
  3. Build a weighted co-activity network from those signals.
  4. Extract dense clusters from that network. A coordinated group knots together into a small, heavily weighted cluster that stands out from the sparse web ordinary accounts sit in.
  5. Sort each flagged cluster into a likely-automated core and the accounts that amplify.
  6. Tag behaviors with DISARM techniques and score the flagged set against the published labels.

DISARM tags are output. Nothing in the feature, detection, or scoring path reads a tag or a label to decide what to flag.

Scoring and controls

The negative class is the is_control field that ships with the data: Indiana includes organic control posts beside the campaign posts, drawn from accounts discussing the same topics in the same windows. Without a native control class there is nothing for the detector to be wrong about, so there is no honest precision figure to report.

The pipeline flags accounts, so scoring happens at account level. Each account gets a majority vote over its own posts: an account counts as IO if at least half its posts are labeled as campaign posts. The flagged set is then compared against those labels.

Limits

Lab metrics like these are an upper bound: this is a fixed, curated, labeled historical dataset with a native control class, and live traffic has none of that structure.

Russia_2 is built to be 91% IO rows, far above what any real feed looks like, and precision degrades as the base rate drops toward natural, much lower levels of IO. The same false-positive rate produces much worse precision at that lower rate. The 0.54 above describes Russia_2. It does not predict what a live feed would produce.

Co-repost timing, duplicate content, hashtag floods and mention swarms are signals of coordination. They say nothing about authenticity, and a tightly organized genuine community can trip the same thresholds as a paid one. A flag from this pipeline is not attribution, and it is not proof that an account is fake. Someone still has to look at it before anyone acts on the result.

The posting-application field in the parquet release is hashed rather than a readable client string, which kills the automation signal on this data. Russia_2 carries 304 distinct hash values, none matching the literal markers the automation check looks for, so the automated share comes back 0.0 for every account, the bot-account technique never fires, and triage gets no automation signal here. The zero is an artifact of the anonymized field, not evidence about the campaign: it says nothing about whether Russia_2 actually used automation, and no automation results were invented to fill the gap.

Schema notes

The second source forced three decisions.

The two sources don't share a control class. Indiana has one; Clemson is positives-only. A bare boolean would have hidden that difference. A label field plus a label-scheme field records where the class came from, and the original boolean survives as a projection of it, so the scoring code did not change. A third source writes its own scheme value rather than overloading an existing one.

Repost linkage and entity fields do not survive Clemson. Indiana gives the reposted post and account for each retweet. Clemson's retweet column is a bare flag with no pointer back to the original, so those fields stay null. Clemson also embeds hashtags and mentions in the tweet text rather than shipping them as fields, so both come back empty instead of guessed at, and a detector reading those fields sees a real absence, not a fabricated value.

The analyst-coded persona label is annotation. Clemson ships Linvill and Warren's own categories (RightTroll, NewsFeed, and so on). They exist only on Clemson rows, and nothing in the detection path reads them. Building on them would make results source-dependent.

Build

Python. polars for data, networkx for graphs. Test-first, 30 tests. Apache 2.0. A synthetic fixture drives a one-command demo of the full pipeline, so the tool is runnable without the gated dataset.

Data note

Public and licensed research datasets only. No dataset is redistributed here, and no account identifiers, cluster memberships, or post content are published. Only aggregate measurements appear on this page. Nothing here identifies individuals, and nothing here attributes the campaign to an actor.
