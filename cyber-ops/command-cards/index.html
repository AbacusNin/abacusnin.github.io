Command Cards

One-liners I actually reach for, the kind that turn a pile of logs into an answer. Every card was run on sample data, so the output you see is real, not drawn. Grep, awk, sed, and friends.

Log analysis01 / 09

Top brute-force IPs

Rank every IP hammering your SSH.

bash /var/log/auth.log
$ grep "Failed password" /var/log/auth.log | grep -oE "([0-9]{1,3}\.){3}[0-9]{1,3}" | sort | uniq -c | sort -rn | head -5
47203.0.113.45 23198.51.100.23 11203.0.113.178 4192.0.2.91 110.0.0.12
"Failed password"every failed SSH login grep -oEprint only the matching IP, extended regex sort | uniq -ccount each IP sort -rnbiggest number first head -5show the top five

What you get

Find every failed SSH login, pull out the source IP, and count them. Now you know who is knocking and how hard. Block the top ones.

Log analysis02 / 09

Bytes out by source

Add up response sizes per client, and find the heavy hitter.

bash /var/log/nginx/access.log
$ awk '{bytes[$1] += $10} END {for (ip in bytes) print bytes[ip], ip}' access.log | sort -rn
176718 10.0.0.5 94038 198.51.100.23 29936 203.0.113.45 7152 192.0.2.91
$1the client IP, field one $10the response size in bytes, field ten bytes[$1] += $10keep a running total per IP END { ... }print once, after the last line sort -rnlargest total first

What you get

awk tallies bytes per client and prints the totals at the end. A cheap way to spot the host quietly exfiltrating, or the scraper eating your bandwidth.

Log analysis03 / 09

Most-hit URLs

What are they actually requesting?

bash /var/log/nginx/access.log
$ awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -5
4 /login 3 /api/data 3 / 1 /static/app.js 1 /admin
awk '{print $7}'pull just the request path sortgroup identical paths together uniq -ccollapse the runs and count them sort -rnmost frequent first

What you get

sort then uniq -c is the count idiom for any column you can isolate. Sort puts identical lines next to each other, uniq -c tallies them. It answers "what is the most common X" every time.

Sanitize04 / 09

Redact before you share

Scrub IPs and emails out of a log in one pass.

bash incident.log
$ sed -E "s/([0-9]{1,3}\.){3}[0-9]{1,3}/x.x.x.x/g; s/[[:alnum:]._%+-]+@[[:alnum:].-]+/[email]/g" incident.log
Alert: beacon to x.x.x.x every 60s, see attachment. Dropped file hash e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855 Second stage from x.x.x.x, sha256 9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08 Contact the analyst at [email] for the full report.
sed -Eextended regex, no backslash soup s/.../x.x.x.x/greplace every IPv4 with a placeholder ;run a second substitution in the same pass /[email]/gmask every email address /gevery match on the line, not just the first

What you get

One pass that swaps every IP and email for a placeholder, so you can drop a log into a ticket or a writeup without leaking addresses. The hashes stay, since those are the IOCs you want to keep.

Text wrangling05 / 09

Slice out the fields

Pull two columns from a delimited file.

bash /etc/passwd
$ cut -d: -f1,7 /etc/passwd
alice:/bin/bash deploy:/usr/sbin/nologin bob:/bin/zsh root:/bin/bash
-d:split each line on a colon -f1,7keep fields one and seven, the user and its shell

What you get

cut is the fastest way to grab specific columns from delimited text. Here, every account and its login shell. Scan for the ones that should be nologin and are not.

Threat intel06 / 09

Pull IOCs from the noise

Lift SHA-256 hashes out of a messy report.

bash report.txt
$ grep -oiE "\b[a-f0-9]{64}\b" report.txt | sort -u
9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08 e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
-oprint only the match, not the whole line -icase-insensitive hex -Eextended regex \b[a-f0-9]{64}\ba 64-character hex string on word boundaries sort -udedupe

What you get

Point it at any report or email and it lifts out just the hashes, ready to drop into a lookup or a block list. Swap the pattern for IPs, domains, or CVE IDs.

Text wrangling07 / 09

Top words, fast

Word frequency without writing a script.

bash notes.txt
$ tr -cs "A-Za-z" "\n" < notes.txt | tr "A-Z" "a-z" | sort | uniq -c | sort -rn | head -5
5 a 4 detection 3 is 2 behavior 1 without
tr -cs "A-Za-z" "\n"turn every run of non-letters into a newline, one word per line tr "A-Z" "a-z"fold to lowercase so Case and case match sort | uniq -ccount each word sort -rn | head -5the top five

What you get

Two tr passes split text into lowercase words, then the count idiom ranks them. Good for skimming what a long log or a dump is really about. Stopwords like "a" rise to the top, which is why real pipelines add a filter.

JSON logs08 / 09

Filter JSON logs

Reach into structured events, pull one field, and count it.

bash events.jsonl
$ jq -r 'select(.action=="login" and .result=="fail") | .user' events.jsonl | sort | uniq -c | sort -rn
3 admin 2 root
jq -rraw output, without the surrounding quotes select( ... )keep only the failed login events .userpull out the username field sort | uniq -c | sort -rncount and rank

What you get

jq reaches into structured logs the way grep reaches into text. Here it keeps only the failed logins and pulls the username, then the count idiom ranks who is being targeted. The same shape works on CloudTrail, Falco, or any JSON-per-line log.

Network09 / 09

Top DNS queries

Count what a capture was trying to resolve.

bash capture.pcap
$ tshark -r capture.pcap -Y "dns.flags.response == 0" -T fields -e dns.qry.name | sort | uniq -c | sort -rn
3 example.com 2 cdn.example.net 1 telemetry.bad.tld 1 api.github.com
-r capture.pcapread a capture file, no live sniffing -Y "dns.flags.response == 0"display filter, only DNS queries -T fields -e dns.qry.nameprint just the queried name sort | uniq -c | sort -rncount and rank

What you get

tshark reads a capture offline and lets you pull any protocol field by name. Every DNS query, counted. A fast way to spot beaconing or a domain nobody should be resolving, without opening the GUI.
