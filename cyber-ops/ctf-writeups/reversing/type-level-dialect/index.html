When the Answer File Stopped Carrying Information

The first part of the answer file narrowed the hidden string. After the state reached zero, every later answer was the same regardless of the characters that followed.

Summary

The challenge. Recover a hidden string from a Haskell type-level transform and aligned question and answer files.

What I did. I parsed answer forms into modular constraints, carried the state through candidate characters, and checked the result by forward simulation.

The result. The candidate reproduced the recorded answers byte for byte, and the submitted full value was accepted by the scoring platform.

The limit. The answer transcript did not determine the key's tail after the absorbing-zero state; the format and theme supplied that part of the candidate.

1. Problem Statement and Threat Scenario

I had a small Haskell program and two aligned text files. One held questions, and the other held the answers the program had produced. The program imported a secret string from a module I did not have. It used that string to choose a different surface form for each answer. I needed to work backward from the source and the transcript to recover the secret.

The flag format helped: a fixed wrapper around a short run of concatenated Title-Case words, which I will write as <prefix>{TitleCaseWords}. That constraint mattered later because the answer forms did not identify every character by themselves. I had the transform, the questions, and the resulting answers. I did not have the module that defined the secret.

This was a static puzzle. There was no live service to exploit, no defender telemetry, and no adversary in the challenge evidence. The useful question was narrower: how much information about a hidden input does this particular transform leave in its outputs?

2. Techniques, Tooling, and Actions Taken

The hint initially looked geographic to me. Its wordplay pointed instead to GHC, the compiler used by the source. Once I recognized that, I stopped treating the answer file as a word game and read the type-level definitions as a program.

I mapped the surface vocabulary first. Each field had several interchangeable forms, and a small numeric index selected one. A question named only some fields for a given character position. I parsed each answer line back into the forms it used, matching the longest form first because some contained spaces. That gave me observed indices for a subset of fields at each position.

My first shortcut failed. I treated positions independently and chose a plausible letter from the right residue class. The next lines stopped matching. Each character also changed the state used for every later one. I went back to the recurrence, carried that state forward with each candidate, and searched within the Title-Case format instead of fixing one character at a time.

That search narrowed the leading part of the key. At a later position, the carried value became zero. Every following answer then used the default form, no matter which characters followed. I used the format and challenge theme for that unconstrained tail. Finally, I regenerated the entire answer transcript from the candidate and compared it byte for byte. The recorded submission of the full value was accepted by the scoring platform.

3. Tooling and Scripts

I used the GHC source to extract the transform and Python 3 to model it. The local analyzer took the question lines, answer lines, form tables, field-to-series mapping, two moduli, and a candidate alphabet. It parsed forms into indices, tracked candidate characters and state, reported how many characters remained possible at each position, and forward-generated answers from a candidate key. It used only the standard library.

This is the small core of the forward model. n is a field's starting series value. M1 selects a surface form; M2 carries the state to the next character.

def run_series(n, key, M1, M2):
    state, forms = n, []
    for char in key:
        value = ord(char)
        forms.append((state * value) % M1)
        state = (state * value) % M2
    return forms

The reverse side needs the actual form table. I matched answer text to a field's longest valid form, read its index, and kept candidate characters whose computed index matched. A character also had to leave a state consistent with later lines. The constraint profile made the important boundary visible: a few choices remained at early positions; after zero, the whole allowed alphabet remained possible.

The recorded validation had two layers. A synthetic fixture checked the general analyzer's parity. For the challenge candidate, the independently generated answer file matched the supplied answers byte for byte, with matching SHA-256 digests in the solve record. That is a consistency check on the model and candidate. It cannot prove that the transcript uniquely determines characters after the zero state.

4. Concept Explanation

GHC can compute over type-level strings and numbers while it checks a program. This challenge made that compile-time work produce answer text. The imported secret supplied characters; the type-level machinery walked them and chose a form for each queried field. GHC was part of the mechanism, which is why the hint mattered.

The math behind the form choice is small. Each field has a starting series number n. A character code multiplies that series' current state. The product modulo M1 chooses an output form. The same product modulo M2 becomes the next state. Seeing one form gives me a remainder, not a character. Several letters can have the same remainder, so I also need the format and later lines to narrow a choice.

Zero changes the problem completely. If the running product becomes zero modulo M2, multiplying it by any later character leaves it zero. All later form indices become zero as well. From that point, the answers are identical for many possible tails. The Title-Case words were a useful language clue, but they were outside information, separate from what the transcript proved.

5. Exploit / Analysis Mechanics

I wrote the state in terms of one running product. Let P(i) be the product of character codes before position i, reduced modulo M2. For a series that begins at n, its state is state_n(i) = n * P(i) mod M2. At position i, the selected form has index state_n(i) * ord(c_i) mod M1. The next product is P(i+1) = P(i) * ord(c_i) mod M2.

That relationship let me avoid solving every field as a separate machine. All the series saw the same character at each step. I only needed to carry one product while checking the form indices for the fields actually asked on that line.

What I observed What it constrained
A surface form in an answer One index modulo M1 for its field
Several queried fields on one line A set of residue conditions on the current character and state
A Title-Case candidate letter A plausible character that still needed later-line checking
A zero state modulo M2 Every later selected index, regardless of later characters

The independent-position guess failed because it satisfied a local remainder while sending the carried product down the wrong path. Propagating the state fixed that mistake. Under the stated format, the recorded search narrowed the informative prefix. The constraint profile then showed a hard stop: after the accumulator reached zero, every allowed character fit every remaining answer line.

I checked the complete candidate by running it forward through my model and comparing the generated answers with the supplied file byte for byte. Matching SHA-256 digests were a convenient way to record that parity. The full candidate also received a reported accepted result from the scoring platform. Those checks answer different questions. Transcript parity tests consistency with the observed answers. The accepted submission resolves the entire candidate, including a tail the transcript could not distinguish.

More field queries against the same post-zero state would still return the default forms. Recovering that tail deterministically would require other information, such as a fresh state or a different transform that had not already collapsed.

6. Lessons Learned

I should have measured each position's candidate count earlier. Once I could see which positions had a handful of letters and which had the whole alphabet, I knew where to spend the search effort. Guessing a single letter from one line hid that distinction.

The other lesson was to carry state through the entire transcript. The parallel field computations looked separate in the source, but they shared the same per-character multiplier. One running product described their joint behavior. That made the inversion manageable and exposed the absorbing-zero point.

I also kept two kinds of correctness apart. Regenerating an output proves a candidate is compatible with the transform. It does not always prove that candidate is the only possible input. Here the answer file stopped distinguishing tails. The format and accepted submission completed the solve.

7. Operational Extrapolation

Individual Practitioner Development

This pushed me to read code that runs at compile time as carefully as code that runs after launch. The useful skills were extracting a recurrence from type-level definitions, turning selected words into modular constraints, and admitting when the inverse stops being unique. A good follow-up exercise would use a modified transform that asks every field and never reaches zero, then measure whether the extra observations actually produce unique characters.

Security Operations

This puzzle did not supply a host, a deployed verifier, runtime behavior, or logs. I have no SOC alert, incident-response step, hunt, or playbook to claim from it. A separate design review could ask whether a real service leaks partial secret information through repeated answers, but that would need an actual system and test data.

Intelligence Operations

There was no collection source, infrastructure, actor, or attribution surface here. I would not turn a puzzle transcript into an intelligence finding. The reusable habit is to state what an observation can and cannot determine before assigning meaning to it.

8. Reusable Tools, Scripts, and Artifacts

The useful reusable piece is the recurrence model paired with a constraint profile. A generic version needs question and answer files, form tables, a field-to-series map, M1, M2, and an allowed alphabet. It can return answer parity, hashes of the generated and observed outputs, per-position candidate counts, and positions that are completely unconstrained.

Part Purpose Limit
Longest-form parser Recover a field's selected index from answer text Needs accurate form tables; overlapping forms require deliberate matching order
State model Reproduce indices and carry P(i) forward Assumes the same multiplier and modular recurrence as the target
Constraint profile Count surviving characters at each position Counts depend on the chosen alphabet and format prior
Forward parity check Compare a full candidate with every answer line A match shows consistency, not uniqueness after collapse

I validated the generic method on a synthetic example during the solve and used the challenge's answer file for full-candidate parity. I would reuse the method by re-reading a new target's actual definitions, replacing the form tables and moduli, then checking how many inputs produce each output. The snippet in Section 3 is the recurrence, not a complete parser for an arbitrary transcript.

13. Visual Artifact

The flow beside the summary traces the solve: read the GHC transform, turn answer words into residues, carry candidate state, find zero, and verify the full candidate. The two calculations at each character deserve to be read together. One product selects a visible form modulo M1; the same product becomes the next state modulo M2.

Branch from the product What happens
product mod M1 Selects a form that appears in the answer transcript when its field is queried
product mod M2 Carries the state into the next character
Carried state becomes zero Every later form index becomes zero, so the transcript loses the tail

That last branch is why the diagram ends with two checks. Forward parity confirmed that my candidate explained the answer file. The accepted entry confirmed the full string, including characters for which the answer file itself had gone silent.
