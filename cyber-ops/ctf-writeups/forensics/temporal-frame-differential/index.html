The Message Between the Frames

I spent too long treating this video like a file container. The useful question was whether any two frames had a relationship.

Summary

The challenge. Recover a concealed 25-character string from a 300x300 static video with no audio.

What I did. I checked the container and pixel distribution, abandoned a file-container hypothesis, scanned frame pairs for correlation, then used their XOR masks and structural checks to read the glyphs.

The result. The recorded solve recovered a 25-character candidate. Independent replay confirmed the frame geometry, 25 glyph windows, and repeated XOR masks; no submission receipt is present here.

The limit. The candidate string is withheld. The offline scanner is a triage proof of concept tested on synthetic cases and the supplied carrier; it has not been measured on production media.

1. Problem Statement and Threat Scenario

I received one file, static.mp4: a 300x300 video at 60 fps for 25 seconds, with 1,500 frames and no audio. It looked like television static. I needed to recover a concealed 25-character string. The prompt's "static analysis" pun gave me a theme, but it did not tell me where the string lived.

This was a puzzle, with no observed adversary. For defensive work, I would treat it as an example of media steganalysis on a file at rest. MITRE ATT&CK T1027.003 includes video among possible carriers. A DFIR analyst who receives a suspicious attachment or file from a share may face the same constraints I did: the file itself, with no host or network record and no known embedding tool.

The useful information appeared when I compared frames. Each frame alone looked like a roughly balanced binary noise field. The repeated relationship between frames gave the puzzle away.

2. Techniques, Tooling, and Actions Taken

I inspected a media file offline. There was no program to execute or live service to query. My validation came from decoding the frames and comparing their pixels.

I first chased a file-container explanation. It cost me several tests. The log below keeps that wrong turn because the reason I abandoned it matters as much as the final XOR operation.

3. Tooling and Scripts

I wrote the solver below to derive the period and offset from correlated frame pairs. It reproduces the recorded triplet geometry and glyph windows. I also built a separate offline frame-relation reviewer for defensive triage. Its usage and test notes describe the input it expects and the benign duplicate-frame case.

#!/usr/bin/env python3
"""
Temporal XOR / frame-differential steganography recovery.

Recovers a glyph sequence hidden in the RELATIONSHIP between frames of an
all-intra binary-noise video. Nothing is visible in any single frame and
nothing useful appeared in the frame averages I tried. The payload exists in the XOR of frame pairs
at a fixed temporal offset.

Usage:
  python3 solve_temporal_xor.py -i static.mp4 -o out/ --width 300 --height 300

Requires: ffmpeg in PATH, numpy, pillow. ffprobe is needed if geometry is not supplied.
Tesseract is optional.
"""

import argparse, itertools, json, os, shutil, subprocess, sys
import numpy as np
from PIL import Image, ImageFilter, ImageOps


def probe(path):
    """Read geometry from the container rather than assuming it."""
    cmd = ["ffprobe", "-v", "error", "-select_streams", "v:0",
           "-show_entries", "stream=width,height,nb_frames,has_b_frames",
           "-of", "json", path]
    d = json.loads(subprocess.run(cmd, capture_output=True, text=True,
                                  check=True, timeout=30).stdout)
    s = d["streams"][0]
    return int(s["width"]), int(s["height"]), int(s.get("nb_frames", 0) or 0)


def extract_luma(path, w, h):
    """Decode to raw grayscale for the binary-luma comparison."""
    if w > 1024 or h > 1024 or os.path.getsize(path) > 100_000_000:
        raise ValueError("carrier exceeds this review script's size limits")
    cap = min(3000, 500_000_000 // (w * h))
    cmd = ["ffmpeg", "-v", "error", "-i", path, "-frames:v", str(cap),
           "-f", "rawvideo", "-pix_fmt", "gray", "-"]
    raw = subprocess.run(cmd, capture_output=True, check=True, timeout=90).stdout
    if len(raw) > 500_000_000 or len(raw) % (w * h):
        raise ValueError("decoded byte count exceeds limit or frame geometry")
    n = len(raw) // (w * h)
    if n > 3000:
        raise ValueError("too many frames for this review script")
    return np.frombuffer(raw, dtype=np.uint8).reshape(n, h, w)


def verify_bit_depth(frames, sample=4):
    """
    Confirm 1 bpp BEFORE thresholding. The claim that matters is not "0 and 255
    are common" but "the decision boundary is sparsely occupied." Check
    thresholded pair equality separately; a sample histogram proves neither
    losslessness nor the behavior of every frame.
    """
    idx = np.linspace(0, len(frames) - 1, sample).astype(int)
    c = np.bincount(frames[idx].reshape(-1), minlength=256).astype(float)
    tot = c.sum()
    return {"mid_band_112_143_pct": 100 * c[112:144].sum() / tot,
            "low_0_15_pct": 100 * c[0:16].sum() / tot,
            "high_240_255_pct": 100 * c[240:256].sum() / tot}


def frame_relatedness_scan(bits, sample_size=20000, sigma=6.0, seed=0):
    """
    Technique-agnostic linear-correlation screen over sampled frame pairs.
    It does not detect every possible relation. Map {0,1} -> {-1,+1} and take a normalized
    Gram matrix; for independent uniform bits the off-diagonal has mean 0 and
    std 1/sqrt(m) under the independent fair-bit model. The threshold is a
    screening choice; corpus false positives still need measurement.
    """
    rng = np.random.default_rng(seed)
    idx = rng.choice(bits.shape[1], min(sample_size, bits.shape[1]), replace=False)
    X = (bits[:, idx].astype(np.float32) * 2 - 1) / np.sqrt(len(idx))
    C = X @ X.T
    np.fill_diagonal(C, 0.0)
    floor = 1.0 / np.sqrt(len(idx))
    hits = [(i, j, float(C[i, j]))
            for i, j in zip(*np.where(np.abs(C) > sigma * floor)) if i < j]
    return hits, floor


def infer_geometry(hits, n_frames):
    """Derive (period, offset) from the hits instead of assuming a triplet."""
    if not hits:
        return None, None
    offs = [j - i for i, j, _ in hits]
    offset = int(np.bincount(offs).argmax())
    starts = sorted(i for i, j, _ in hits if j - i == offset)
    if len(starts) < 2:
        return None, offset
    diffs = np.diff(starts)
    period = int(np.bincount(diffs).argmax()) if len(diffs) else None
    if period and n_frames % period != 0:
        for p in range(1, 13):
            if n_frames % p == 0 and p > offset:
                period = p
                break
    return period, offset


def segment_runs(bits, period, offset):
    """
    Group-wise XOR popcount, then run-length segment on the RAW distance.
    Collapsing to a zero/nonzero predicate first would preserve only the
    blanking cadence and destroy the per-character fingerprint.
    """
    n_groups = bits.shape[0] // period
    d = [int(np.count_nonzero(bits[period * t] != bits[period * t + offset]))
         for t in range(n_groups)]
    runs = []
    for value, grp in itertools.groupby(enumerate(d), key=lambda x: x[1]):
        grp = list(grp)
        runs.append((value, grp[0][0], len(grp)))
    return d, runs


def accumulate_glyph(bits3d, period, offset, start, length, blur=2.0, rel_thresh=0.35):
    """
    Render the repeated XOR mask for OCR. In this carrier, each XOR is the
    same exact mask within a glyph run. Blurring helps OCR but does not recover
    a signal missing from a single pair.
    """
    h, w = bits3d.shape[1], bits3d.shape[2]
    acc = np.zeros((h, w), np.float32)
    for t in range(start, start + length):
        acc += (bits3d[period * t] ^ bits3d[period * t + offset])
    acc /= max(length, 1)
    im = Image.fromarray((acc * 255).astype(np.uint8)).filter(ImageFilter.GaussianBlur(blur))
    a = np.array(im, dtype=np.float32)
    peak = a.max() if a.max() > 0 else 1.0
    return ((a > peak * rel_thresh) * 255).astype(np.uint8)


def cross_validate(candidate, distances):
    """
    In this carrier, exact XOR masks repeat within each glyph window. A repeated
    character should map to one popcount, but different glyphs can collide.
    Brace mirrors are one plausible collision, not a uniqueness proof.

    LIMITATION (see writeup §6): this constrains REPEATED characters only.
    A character appearing exactly once is unconstrained -- the check is a
    consistency test, not a uniqueness proof.
    """
    if len(candidate) != len(distances):
        return False, ["length mismatch"]
    fwd, rev, conflicts = {}, {}, []
    for ch, dist in zip(candidate, distances):
        fwd.setdefault(dist, set()).add(ch)
        rev.setdefault(ch, set()).add(dist)
    for dist, chars in sorted(fwd.items()):
        if len(chars) > 1 and chars != {"{", "}"}:
            conflicts.append("popcount %d -> %s" % (dist, sorted(chars)))
    for ch, ds in rev.items():
        if len(ds) > 1:
            conflicts.append("char %r -> %s" % (ch, sorted(ds)))
    return not conflicts, conflicts


def ocr_glyph(mask, path):
    """OCR is a NOISY channel here; never trust it standalone (see writeup §6)."""
    im = Image.fromarray(255 - mask)
    ImageOps.expand(im, 60, 255).save(path)
    if not shutil.which("tesseract"):
        return ""
    wl = ("abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"
          "0123456789_{}!@#$%^&*")
    r = subprocess.run(["tesseract", path, "stdout", "--psm", "10",
                        "-c", "tessedit_char_whitelist=" + wl],
                       capture_output=True, text=True)
    return r.stdout.strip().replace(" ", "")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("-i", "--input", required=True)
    ap.add_argument("-o", "--outdir", default="out")
    ap.add_argument("--sample", type=int, default=20000)
    ap.add_argument("--sigma", type=float, default=6.0)
    ap.add_argument("--width", type=int)
    ap.add_argument("--height", type=int)
    a = ap.parse_args()
    os.makedirs(a.outdir, exist_ok=True)

    if (a.width is None) != (a.height is None):
        ap.error("supply both --width and --height or neither")
    w, h = (a.width, a.height) if a.width else probe(a.input)[:2]
    frames = extract_luma(a.input, w, h)
    print("[+] %d frames of %dx%d" % (len(frames), w, h))

    depth = verify_bit_depth(frames)
    print("[+] sampled mid-band 112-143: %.3f%%  (verify pair equality separately)"
          % depth["mid_band_112_143_pct"])
    if depth["mid_band_112_143_pct"] > 5.0:
        print("[!] boundary not empty -- thresholding will inject errors")

    bits3d = (frames >= 128).astype(np.uint8)
    bits = bits3d.reshape(len(frames), -1)

    hits, floor = frame_relatedness_scan(bits, a.sample, a.sigma)
    print("[+] relatedness: %d pairs > %.1f sigma (floor %.4f)" % (len(hits), a.sigma, floor))
    if not hits:
        print("[!] no related frames under this sampled linear-correlation test")
        return 1

    period, offset = infer_geometry(hits, len(frames))
    print("[+] inferred geometry: period=%s offset=%s" % (period, offset))
    if not period:
        return 1

    d, runs = segment_runs(bits, period, offset)
    glyph_runs = [r for r in runs if r[0] != 0]
    print("[+] %d runs, %d glyph windows" % (len(runs), len(glyph_runs)))

    masks, dists, ocr = [], [], []
    for k, (dist, start, length) in enumerate(glyph_runs):
        m = accumulate_glyph(bits3d, period, offset, start, length)
        masks.append(m); dists.append(dist)
        ocr.append(ocr_glyph(m, os.path.join(a.outdir, "g%02d.png" % k)))

    cols = min(13, len(masks)) or 1
    rows = (len(masks) + cols - 1) // cols
    cell = 120
    grid = Image.new("L", (cell * cols, cell * rows), 0)
    for i, m in enumerate(masks):
        grid.paste(Image.fromarray(m).resize((cell, cell), Image.LANCZOS),
                   ((i % cols) * cell, (i // cols) * cell))
    grid.save(os.path.join(a.outdir, "glyphs.png"))

    print("[+] popcounts: %s" % dists)
    print("[+] OCR (UNRELIABLE alone): %r" % "".join(ocr))
    print("[+] %d distinct popcounts over %d glyphs -- repeated counts need visual review"
          % (len(set(dists)), len(dists)))
    return 0


if __name__ == "__main__":
    sys.exit(main())

4. Concept Explanation

The carrier

After decoding, the luma is almost a binary field. Each 300x300 frame has 90,000 pixels, with roughly half on each side of 128. MPEG-4 Part 2 introduces values around the extremes. The four frames sampled in the original check contained zero pixels in 112-143. Across all 1,500 decoded frames, I counted 493 mid-band pixels out of 135 million. That is a tiny fraction, but the four-frame sample should not have been described as a universal empty boundary. The 251 exact A/C pairs below show that thresholding preserved those pairs' equality in this decode; they do not prove every source bit survived compression.

The embedding

I grouped frames into triplets (A, B, C). In a blank triplet, thresholded C equals A. In a glyph triplet, A XOR C yields a glyph-shaped mask. B acts as unrelated filler. I initially described C as independently rerandomized inside the glyph. The decoded frames contradict that: all XOR masks within each of the 25 glyph windows are exactly identical, including their pixel positions. In this file, C is better described as a deterministic toggle of the mask on A.

The payload is therefore:

XOR(A, C) = 0                        in blank triplets
XOR(A, C) = fixed glyph mask         in each glyph window

Why this defeats every standard steganalysis reflex

This explains why so many of my first tests went nowhere.

Frame averaging failed here. I averaged raw frames, expecting the noise to settle and a persistent picture to appear. Instead the average approached a flat gray field. That operation discarded the pair identity I needed. Averaging the XOR masks, by contrast, preserves the glyph, though one pair is enough in this carrier.

Per-frame statistics gave me no lead. White-pixel density across all 1,500 frames ranged from 0.4940 to 0.5054. None crossed my broad 0.45-0.55 check. That observation describes this file; it does not establish that every possible per-frame detector would fail.

Entropy did not distinguish my hypotheses. The packed bitstream measured 7.997 bits per byte. Compressed material and random material can both look like that. I treated the number as confirmation for too long.

My byte-signature sweep found nothing. I checked five orientations, two polarities, two bit orders, eight shifts, and nine zlib window settings, with no magic or decompression hit. This rules out those tested layouts. It does not rule out every possible intra-frame encoding.

The decisive structure was in which two frames I compared. A global mean or histogram threw that pairing away. Once I kept frame order and tested relationships directly, the signal was large.

The detection primitive that does work

I mapped sampled bits from {0,1} to {-1,+1} and compared frame vectors with a normalized dot product. Under an independent fair-bit model, a pair has expected correlation near zero and standard deviation 1/sqrt(m). With m = 20,000, that scale is about 0.0071; the strong pairs reached 1.0000. The 6/sqrt(m) cutoff is a useful screen, but I would measure false positives on a real media set before treating it as calibrated detection.

The test made fewer assumptions about the embedding than my container decoder did. It still has a boundary: a linear correlation screen will miss some nonlinear relationships. Here it found 500 related pairs, all at lag two.

5. Exploit / Analysis Mechanics

The invariant that was violated

I tested the video's apparent story: 1,500 independent frames of random static. Its per-frame balance looked plausible. Its pairwise behavior did not. Five hundred frame pairs at lag two passed the relatedness threshold. The exact mask repetitions within glyph windows make the dependence even clearer. Ordinary animation can also repeat frames, so the relation is an investigation lead, not a verdict by itself.

Derivation

Step 1 - establish the bit field (ST.3). I thresholded decoded luma at 128 after checking the distribution. Four sampled frames had no 112-143 values; the full decode had 493. I then checked equality and XOR behavior on the thresholded frames rather than assuming a globally lossless reconstruction.

Step 2 - challenge the specific file-container model (ST.8). The reference decoder I was following expected a padded tail. The final frame ended with a constant run of only 4 pixels, while every frame stayed near 50% white. That contradicted this implementation's expected layout. It did not exclude all schemes that hide files in video.

Step 3 - detect relatedness (ST.9). The sampled correlation scan found 500 pairs at offset +2, repeating every three frames. That gave me the triplet structure (A, B, C).

Step 4 - recover exact structure (ST.10). I hashed the thresholded frames and counted 251 ABA triplets, 249 ABC triplets, and 1,249 unique frames. "Exact" here means exact after decoding and thresholding at 128; the classification depends on that representation.

Step 5 - separate clock from payload (ST.11a -> ST.12). I briefly treated the ABA/ABC sequence as 500 payload bits. Its runs were (1,11),(0,10),(1,10),(0,10).... Twenty triplets take one second at 60 fps. That regularity showed a blanking clock. The nonzero windows carried the glyph information in their XOR masks and Hamming distances.

Step 6 - segment (ST.13). I kept each raw Hamming distance and found 25 nonzero windows: 24 held ten triplets, and the final one held nine. Each window repeated one popcount. Equal counts alone would not prove equal spatial masks; different masks can share a count. I checked the masks themselves and found exact equality within all 25 windows. A zero/nonzero-only sequence would have hidden that per-glyph structure.

Step 7 - render the glyph (ST.14). The original solver averaged XOR(A, C) over a run, blurred it, and applied a threshold at 0.35 of the peak for OCR. On this carrier, averaging identical masks changes nothing about the recovered pixels. The blur can make a glyph easier for OCR to read, but a single frame pair already contains the full binary mask. That was the largest correction I made after replaying the file.

Step 8 - read and cross-validate (ST.15/ST.16). Tesseract gave me a noisy reading. The repeated popcounts provided a consistency check on repeated characters, with the limits described in Section 6.

The fingerprint channel

Because each glyph window repeats one exact XOR mask in this file, popcount(XOR(A,C)) is constant within the window. The 25 glyph positions yielded 17 distinct counts. Repeated counts gave me a possible character-class skeleton before OCR, although count collisions can join different glyphs:

Popcount Positions Inference
8098 3, 6 the two identical letters of the 6-char prefix

The recorded reading puts braces at positions 7 and 25, both with count 8991. Mirrored glyph shapes can share a count, so this is consistent with the reading. It does not prove those two characters from popcount alone.

6. Lessons Learned (Practitioner Perspective)

What the exercise validated

A broad relation test gave me the pivot. I had tried twelve technique-specific checks without finding the message. The pairwise scan took about thirty seconds in the recorded run and found the lag-two pattern. I should have asked about frame relationships earlier.

The null model gave me a scale. 1/sqrt(m) told me how small independent-frame correlations should be under a fair-bit model. The observed 1.0000 peaks were far away. I would still validate the cutoff on a representative media set before using it as an alert threshold.

Exact comparison before aggregation. Hashes and XOR preserved the frame-pair signal that my raw-frame averages had erased.

What the exercise surfaced as gaps

I stayed with the wrong precedent too long. The 1-bit field led me to a video-as-file-container tool family. Its diagnostics returned a bad metadata version, bad checksum, impossible block size, a measured block size of one, and a stock encoder tag where that reference used a custom tag. I treated each as a parameter issue. I then swept 17 parameter values and many decompression layouts. I should have written the reference implementation's expected padded-tail behavior down first. A single tail check would have sent me back to the video much sooner.

I gave entropy too much weight. A result of 7.997 bits per byte fits both compressed data and random data. It could not decide between those explanations. I nevertheless treated it as support for a compressed payload and prolonged the dead end. I have no measured likelihood ratio for those specific hypotheses; the point is that this one number did not discriminate them.

I nearly did it again with the ABA/ABC sequence. I packed the pattern as a candidate payload before checking its runs. The 10/10 cadence showed it was a clock. This time I caught the mistake before feeding it into a decoder.

I trusted OCR, then overstated the correction. Tesseract misread five of 25 glyphs, including an empty first character and $ for a closing brace. Visual review and the popcount classes helped correct the reading, but the class check cannot catch every bad character. Seven repeated-count classes cover 15 positions. The other 10 are singletons, and changing one of those characters passes the class check. I proved that with a negative control. The class map is a consistency test for repeated positions; the singleton readings still depend on the rendered glyphs.

I used the wrong codec term once. I called this a B-frame difference. The stream has has_b_frames=0, and the frame census reports 1,500 I frames. This is a comparison between decoded frames in an all-intra stream. The term matters because B-frames would imply a codec structure that is absent here.

The replay corrected my mask model too. Constant Hamming distance led me to describe fresh randomization inside each glyph. When I compared the actual XOR arrays, each run repeated one exact mask. I now separate the observed mask equality from the mechanism I once inferred.

Exercise behavior mapped to operational behavior

Exercise behavior Operational analogue
Eventually tested the reference decoder's padded-tail expectation State disconfirming evidence for an attribution or encoding hypothesis before a broad parameter sweep
Asked whether frames were related Use broad triage before matching an unfamiliar file to one known tool
Used the 1/sqrt(m) null scale Start with an explicit model, then tune and validate on the operational dataset
Checked OCR against repeated-count classes Corroborate a noisy read with another observable, within that observable's coverage
Changed a singleton as a negative control Measure what a validator actually rejects
Mistook entropy for confirmation Keep high entropy as a description, not a payload diagnosis

Transferable principles

  1. Write down the falsifier. I should have checked for the expected padding before the parameter sweep.
  2. Revisit a hypothesis when its diagnostics disagree repeatedly. Sweeps can be useful, but only after the core model survives basic checks.
  3. Preserve pair identity. Hash or XOR frame pairs before reducing them to averages.
  4. Test the validator with a wrong answer it ought to reject. My singleton mutation showed exactly where the popcount check stops helping.
7. Extrapolation

Individual practitioner skill development

This exercise pushed me past the first reflexes of LSB checks, steghide, and binwalk. I had to retain order and compare samples. The same habit helps with near-duplicate image review, reused-keystream clues in cryptography, and timing-channel analysis. Those problems need different tests, but all can hide structure in relationships rather than in one isolated object.

Security operations (SOC, IR, threat hunting)

For a real adversarial file at rest, T1027.003 is a relevant technique class. T1001.002 would be relevant if steganography were used in a command-and-control channel; no such channel appears in this challenge. ATT&CK documents real media-steganography cases, but this puzzle does not establish an actor or campaign.

I have no host or network telemetry for this case. I cannot name a process, command line, registry event, or beacon from the file alone. A real operator who generated, opened, or transferred such a file might leave those traces; they would require separate collection.

What it does produce is a threat-hunt hypothesis for media at rest:

  • Hypothesis: a media file transiting an egress path or resting on a share carries a covert channel in frame-pair relationships rather than pixel content.
  • Collection: the media files themselves. Not logs.
  • Analytic: decode to frames, quantize only after checking the pixel distribution, then examine correlation and exact equality at repeated lags. A regular lag-two, period-three pattern deserves review. Legitimate animation, test footage, and duplicated frames can produce relatedness too.
  • Triage clue: this file is about 58 MB for 25 seconds at 300x300, roughly 18.7 Mbit/s. That is high for its apparent content, but bitrate depends on codec settings and is only a prioritization cue. I did not measure a threefold compression penalty against a comparable encode.

Intelligence operations (SIGINT, IO/IW, OSINT, attribution)

The concealment is temporal: the relevant mask emerges when I compare two samples at the right offset. The (period, offset) pair tells an analyst where to look. I would call it analysis geometry, not a cryptographic key.

For a collection workflow, the lesson is to keep the original sequence and test relationships when the usual per-frame checks are inconclusive. A negative pairwise scan would still have limits: sampling, lag range, quantization, and nonlinear encodings can all hide a relation. I would report what the analytic tested, never that it "cleared" every possible covert channel.

The general question travels beyond video. Repeated display captures, sector images, telemetry samples, and ciphertexts can all carry relationships between observations. Each medium needs its own null model; the video threshold here should not be copied over unchanged.

8. Reusable Tools, Scripts, and Artifacts

Artifact 1 - frame_relatedness_scan() (see §3)

Usage: the source solver below takes thresholded video frames, samples m = 20,000 pixels, and computes a frame-pair correlation matrix. The offline reviewer takes bounded raw gray frames and scans configurable lags in blocks. At 20,000 independent fair-bit samples, 1/sqrt(m) is about 0.0071. Other media and benign corpora need their own evaluation.

Usage note: the correlation screen can surface identical, complementary, or partially correlated pairs. It cannot explain why they are related. The synthetic checks include a fixed-offset positive, benign duplicate frames that also alert, and an independent-noise near miss.

Artifact 2 - cross_validate() (see §3)

Usage: I paired OCR with repeated popcount classes and a known format prefix. The challenge solver contains the helper. This check can be adapted to another noisy recognizer only when that other task has a justified structural invariant.

Usage note: it constrains repeated symbols only. Singletons pass without this check. Here, 15 of 25 positions were constrained and 10 were not. Different glyphs can also share a count.

Artifact 3 - Media steganalysis triage order

Ordered by cost-to-discriminating-power, hardest-won lesson first:

1. Container/codec sanity      - all-intra for noise-like content? bitrate vs resolution?
                                 (cheap, and a strong prior that something is off)
2. Marginal distribution       - histogram: how many levels? is the decision boundary empty?
                                 (establishes bit depth; NOT evidence of a payload)
3. DEFINE THE FALSIFIER        - before adopting any container/tool hypothesis, write down
                                 the single observation that would kill it. Run THAT first.
4. Relation scan               - are any two samples linearly related? (null-model
                                 threshold; the highest-value probe on an unknown embedding)
5. Exact structure             - hash before you average; equality survives what statistics destroy
6. Characterize before consume - run-length/periodicity check any extracted sequence BEFORE
                                 feeding it to a decoder. Clocks look like payloads.
7. Cross-validate the read     - pair the noisy channel with a structural invariant, then
                                 negative-control the invariant to learn its real coverage

Anti-pattern: entropy as a payload test. ~8.0 bits/byte is equally consistent with
compressed data and with uniform noise. Likelihood ratio 1. It narrows nothing.

Analytic seed (untested against production telemetry)

The original investigation also produced this broader triage sketch. The linked reviewer implements the pairwise core; metadata scoring and file collection remain proposals:

ANALYTIC: inter-frame relation anomaly in media at rest
FOR each candidate media file:
    meta <- probe(file)
    # Prior 1: all-intra plus noise-like content may merit inspection.
    IF meta.pict_types are all I AND meta.frame_count > 100:
        score += 1
    # Prior 2: bitrate grossly disproportionate to resolution x duration.
    IF meta.bitrate / (meta.width * meta.height * meta.fps) > threshold_bpp:
        score += 1
    frames <- decode_luma(file)
    # Prior 3: a 2-level (or few-level) luma histogram in "camera" content
    IF histogram_is_multimodal_with_empty_boundary(frames):
        score += 2
        bits <- threshold(frames)
        hits, floor <- frame_relatedness_scan(bits, m=20000, sigma=6)
        # Review: bit-identical or highly correlated frames at a fixed offset.
        IF hits is non-empty AND offsets(hits) cluster on a single value:
            score += 5
            ALERT "inter-frame covert channel candidate:
                   period=P offset=O, N related pairs, max corr=C"

Log source / data pipeline requirements. None in the SIEM sense. This analytic requires the media files themselves, not telemetry: - a file-retrieval path (EDR file collection, DLP quarantine, share crawl, or egress proxy capture with body retention); - decode capacity such as ffmpeg. The proof of concept reads bounded raw gray frames, samples pixels, and compares lags in blocks; - offline placement or a quarantine queue. I did not test inline performance.

Fidelity expectations, false-positive surfaces, tuning. - Priors 1-3 alone are weak; legitimate content triggers them (screen recordings, animation with static frames, dithered/1-bit art, synthetic test patterns). Do not alert on them. - A repeated lag and period strengthen the lead. Legitimate loops, animation, and test patterns can have the same structure. The benign fixture demonstrates a valid alert on harmless repeated frames. - sigma multiplies the null standard deviation for independent fair bits. Real media violate that model, and the scan tests many dependent pairs. I do not infer an operational false-positive rate from six sigma. - Expected false-positive rate: unmeasured on a real media collection. The positive, benign repeat, and independent near miss test local logic only.
