# Stateful LLM gatekeeper assessment checklist

This is a reusable assessment companion derived from the court exercise. Use it only on a target you are authorized to test. It records observed behavior separately from planned probes and keeps the disclosure result separate from external acceptance.

1. Record the initial authorized identity, visible rank or state, protected object, and permitted test scope. Save the exact prompt and full reply for each test.
2. Send one low-impact baseline request. Record the response, state change, and any stated form rule. Do not treat a drafted payload as a test result.
3. If the gate describes its rules, ask for the rubric in the form it accepts. Record the rules as the gate's claims, then test them one at a time. A fluent reply alone is not evidence of a state transition.
4. If the exercise calls for distinct qualifying actions, submit one per turn. Check the visible ledger after each, including the recorded action and rank. Repeated actions should not silently earn new credit.
5. At the final step, compare a refusal with each stated condition. Change only the missing condition when possible, then record the next result. Preserve failed attempts in the timeline.
6. Record whether the target actually disclosed the protected value. Record a separate platform or owner confirmation if one exists. Redact the value from a public report.
7. For a production gateway, test an authenticated subject without a grant, a forged rank in user text, replay of a qualifying action, malformed request form, an eligible subject's own object, and another subject's object. Check the server's decision and release logs. A model's agreement is not an authorization result.

In the original exercise, only the direct request and acrostic were sent from the proposed bypass ladder. The character-by-character, fictional, encoded, and instruction-dump ideas stayed unsent. The checklist is a generalization; its behavior on another gatekeeper has not been validated.
