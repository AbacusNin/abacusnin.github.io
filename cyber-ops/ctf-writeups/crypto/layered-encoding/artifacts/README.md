# Defensive proofs of concept: layered encoding

These files are newly authored local aids inspired by the six encoding exercises. They contain invented inputs. They are not recovered challenge artifacts or evidence of an intrusion.

Run `python -B test_pocs.py` from this folder. `decode_lab.py` exposes `decode_once`, `decode_stack`, and `encode_stack` for an analyst who has selected the layer order. It takes at most 8,192 characters and four layers; output is ASCII only. It never executes decoded content. The test suite covers binary, octal, hex, Base64, three-layer round trips, and malformed near misses. A recognizable alphabet or padding is a clue, not proof of the scheme.

`process_hunt.py` takes a local UTF-8 JSONL file of process creation events. Map your sensor's fields to `event_id`, `image`, and `command_line` before use. A matching Windows PowerShell or pwsh process with a valid `-e`, `-enc`, or `-EncodedCommand` UTF-16LE Base64 argument produces a small JSON alert. The alert omits raw and decoded command text. Command lines can contain secrets, so restrict the input file and review access. The positive test uses an invented encoded command; benign non-PowerShell Base64 and malformed or absent arguments are negatives. A legitimate encoded admin command remains a review item and is an expected false positive for maliciousness. This is a syntax and behavior test on synthetic events only; no Sysmon, Windows Security, PowerShell, SIEM, or production telemetry was tested. The pattern covers these argument forms, not every PowerShell abbreviation or quoting variation. Tune with local administrative baselines and inspect the script content under controlled procedures before escalating.

Neither script scans encrypted traffic, decompresses payloads, infers attacker intent, or claims to identify all layered encodings. Keep decoded output isolated from any execution path. Expected test result: four tests pass. Observed locally: recorded in the private publication review.
