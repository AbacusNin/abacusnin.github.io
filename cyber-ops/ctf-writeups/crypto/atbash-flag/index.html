The Flag That Read Backward

The series talked about XOR. This first key gave me a much smaller problem: a flag-shaped string whose letters had been reflected across the alphabet.

Summary

The challenge. Recover the flag hidden in one short encoded token, the first key in a larger series.

What I did. I inspected its characters and delimiters, tried Atbash, and checked the candidate before submitting it.

The result. The decoded answer was accepted by the challenge platform. The worked example below uses a separate, generic string.

The limit. The actual token and flag are withheld, so the worked example demonstrates the method rather than reproducing the accepted submission.

1. Problem Statement and Threat Scenario

I had a short token and a taunting message. This was the first key in a series whose later framing mentioned combining keys with XOR. My immediate job was narrower: recover the flag represented by this one token. I had no program to reverse, no service to query, and no traffic capture. The token itself was the entire artifact.

The answer was expected to fit a <ctf-prefix>{...} wrapper. I do not show the challenge's actual token or recovered flag here. The example throughout this page is a generic pair made to show the same transform. The challenge was a cipher puzzle, with no observed intrusion, victim, or operational threat model.

2. Techniques, Tooling, and Actions Taken

I started by looking at the token before reaching for the series hint. Its braces, digits, and underscores were already in place. The body used printable characters and kept the shape of a flag. That made a letter-by-letter substitution a good first test. The shape alone could not eliminate XOR; an XOR result can also be printable. I had no key or byte representation pointing me to that route for this first token, though.

Atbash was the cheapest test. I reflected each letter across the alphabet, leaving the braces, underscores, and other nonletters alone. The result read as ordinary English and named the technique. I then ran the transform again to make sure my decoder returned the starting text. Finally, I checked the flag wrapper and submitted the actual recovered value. The platform accepted it.

I did not need to run Caesar shifts or search for an XOR key after that result. Those were alternatives I considered, not failed executions. The series' XOR instruction still mattered for the later combination step; it did not describe the encoding of this first key.

3. Tooling and Scripts

I used a small Python 3 codec. It has no third-party dependencies. It changes ASCII letters in either case and passes every other character through. The codec and sample fixture are available alongside this page; both use only the generic example.

import sys

SAMPLE_CT = "uozt{zgyzhs_rh_zm_rmelofgrlm}"


def atbash(text: str) -> str:
    out = []
    for char in text:
        if "a" <= char <= "z":
            out.append(chr(ord("z") - (ord(char) - ord("a"))))
        elif "A" <= char <= "Z":
            out.append(chr(ord("Z") - (ord(char) - ord("A"))))
        else:
            out.append(char)
    return "".join(out)


text = sys.argv[1] if len(sys.argv) > 1 else SAMPLE_CT
result = atbash(text)
print(result)
assert atbash(result) == text

Run it with python3 atbash_codec.py "uozt{zgyzhs_rh_zm_rmelofgrlm}". The sample prints:

flag{atbash_is_an_involution}

The assertion checks the implementation's round trip. It cannot, on its own, prove that a candidate is the intended flag: Atbash will round-trip any input. Readable content and the accepted submission supplied the stronger checks in this case.

4. Concept Explanation

A monoalphabetic substitution uses one fixed replacement for each letter, wherever that letter appears. Atbash uses the alphabet in reverse order: a maps to z, b to y, and m to n. The same mapping works backward. In symbols, atbash(atbash(x)) == x for text handled by the codec above.

The unchanged braces and underscores helped me recognize the flag's structure before I knew its letters. Atbash preserved those characters because the codec only changes the Latin alphabet. That is a useful clue, though other transformations can preserve punctuation too. The Handbook of Applied Cryptography, Section 7.3.2, places simple substitution among the classical ciphers and explains why it is unsuitable as modern protection.

5. Exploit / Analysis Mechanics

For a lowercase letter at position i from a = 0, Atbash returns the letter at 25 - i. The same rule applies separately to uppercase. Digits, braces, underscores, and punctuation keep their positions and values. There is no secret Atbash key to recover; the work is recognizing the mapping and checking the decoded text.

On the public example, uozt becomes flag, and zgyzhs becomes atbash. A second pass restores uozt{zgyzhs_rh_zm_rmelofgrlm} exactly. This shows that the implementation performs the intended reflection. The example's English phrase was chosen for demonstration and was never the challenge submission.

For the actual challenge, I used three checks in order: the decode read sensibly, it fit the expected flag structure, and the platform accepted the submitted value. The last check establishes the challenge outcome. I cannot use the round trip to claim that Atbash is uniquely identified from character shape alone. This method also assumes Latin letters. A keyed substitution or a different alphabet would need a different analysis.

6. Lessons Learned

The series hint almost decided my first move for me. Looking at the token was faster. Its printable, delimiter-preserving form suggested a substitution worth testing, and Atbash resolved it without a search. I would make that quick representation check again before applying the larger story of a multi-part challenge to a single artifact.

The round trip was still worth doing. It caught the kind of coding mistake that can hide behind a plausible output, especially around uppercase letters and punctuation. I kept its meaning narrow: it checks the codec, while the readable answer and platform response check the solve. I had no reason to keep transforming this token after acceptance.

7. Operational Extrapolation

Individual Practitioner Development

This gave me a compact exercise in separating representation from cipher choice. I could recognize a structure-preserving transform, test the simplest candidate, and verify the code without confusing that verification with proof of the answer. A sensible next exercise would add a keyed substitution or a polyalphabetic cipher, then use known plaintext to test a proposed key. Recognition alone would not recover that text.

Security Operations

I have no production detection result from this challenge. It supplied a static string, and my decoder ran locally. In a real investigation, a similarly obfuscated string would need context: where it was found, what process used it, and what behavior followed its decoding. That context could justify an analytic. This token alone does not.

Intelligence Operations

Recognizing a classical cipher is useful practice for reading encoded material. This case supplied no collection source, actor, campaign, or attribution evidence. I would preserve the decoded text and its transform in an intelligence work record, but I would not turn the puzzle into a claim about an adversary.

8. Reusable Tools, Scripts, and Artifacts

The Atbash codec accepts one string and prints its reflected form. It needs Python 3 and the standard library only. Its built-in sample makes a quick smoke check possible; the sample fixture records both sides of that example. Neither file contains the challenge value. The codec works on ASCII Latin letters and leaves all other characters unchanged.

I also keep a short triage sequence for similar puzzles:

  1. Record the raw character set, length, and delimiters.
  2. Ask which transforms could leave that structure intact. Keep other possibilities open.
  3. Try inexpensive candidates such as Atbash or ROT-N before a keyed search when the token supports it.
  4. Check implementation behavior separately from answer correctness.
  5. Let the artifact and the final verifier settle the result, even if a series theme suggests another route.

The codec makes substitution checks repeatable. It only applies Atbash, and its round-trip assertion cannot identify an unknown cipher.

9. Framework Applicability and Mapping
